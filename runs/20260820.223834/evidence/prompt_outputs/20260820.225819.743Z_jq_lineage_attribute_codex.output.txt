<requirement name="filter-streams" stories="core-generators">
A jq program is a "filter": it takes an input, and produces an
output.
</requirement>
<requirement name="lex-jq-programs" stories="frontend-lexer">
You can write comments in your jq filters using `#`.
</requirement>
<requirement name="parse-jq-syntax" stories="frontend-parser">
Parenthesis work as a grouping operator just as in any typical
programming language.
</requirement>
<requirement name="diagnose-invalid-programs" stories="frontend-diagnostics">
The `break $label_name` expression will cause the program to act as though the nearest (to the left) `label $label_name` produced `empty`.
</requirement>
<requirement name="core-values-and-operators" stories="core-expressions">
jq supports the same set of datatypes as JSON - numbers,
strings, booleans, arrays, objects (which in JSON-speak are
hashes with only string keys), and "null".
</requirement>
<requirement name="runtime-errors" stories="core-errors">
If you try to add a string to an object you'll get an error message and
no result.
</requirement>
<requirement name="generator-utilities" stories="core-utilities">
`empty` returns no results. None at all. Not even `null`.
</requirement>
<requirement name="discover-paths" stories="paths-discovery">
`path(path_expression)` Outputs array representations of the given path expression
in `.`.
</requirement>
<requirement name="mutate-values-by-path" stories="paths-mutation">
The builtin function `setpath` sets the `PATHS` in `.` to `VALUE`.
</requirement>
<requirement name="assign-values" stories="paths-assignment">
Assignment works a little differently in jq than in most
programming languages.
</requirement>
<requirement name="conditionals-and-comparisons" stories="control-conditionals">
jq supports the normal Boolean operators `and`, `or`, `not`.
</requirement>
<requirement name="reduce-and-foreach" stories="control-reductions">
The `reduce` syntax allows you to combine all of the results of
an expression by accumulating them into a single answer.
</requirement>
<requirement name="variables-and-scope" stories="control-bindings">
In jq, all filters have an input and an output, so manual
plumbing is not necessary to pass a value from one part of a program
to the next.
</requirement>

You can give a filter a name using "def" syntax:
</requirement>
<requirement name="structural-builtins" stories="builtins-structural">
For any filter `f`, `map(f)` and `map_values(f)` apply `f`
to each of the values in the input array or object, that is,
to the values of `.[]`.
</requirement>
<requirement name="string-and-format-builtins" stories="builtins-strings">
The `tojson` and `fromjson` builtins dump values as JSON texts
or parse JSON texts into values, respectively.
</requirement>
<requirement name="regular-expression-filters" stories="builtins-regex">
jq uses the
[Oniguruma regular expression library](https://github.com/kkos/oniguruma/blob/master/doc/RE),
as do PHP, TextMate, Sublime Text, etc, so the description here will focus on jq specifics.
</requirement>
<requirement name="numeric-and-date-builtins" stories="builtins-numeric">
jq currently only has IEEE754 double-precision (64-bit) floating
point number support.
</requirement>
<requirement name="streaming-and-sql-builtins" stories="builtins-streaming">
With the `--stream` option jq can parse input texts in a streaming
fashion, allowing jq programs to start processing large JSON texts
immediately rather than after the parse completes.
</requirement>
<requirement name="environment-and-io" stories="builtins-io">
At this time jq has minimal support for I/O, mostly in the
form of control over when inputs are read.
</requirement>

# FEATURE: Paths Discovery

| Field       | Value |
|-------------|-------|
| Version     | 20260820 V1 |
| Description | Discover, enumerate, and read values through jq path expressions. |
| Depends On  | ARCHITECTURE.md, FEATURE-Core-Utilities.md |
| Provides    | path, paths, getpath |
| Consumes    | ordered generator evaluation, indexing, recursion, filtering |

## Questions

- None.

## Capability

Path discovery evaluates exact and generated path expressions against immutable jq values. `path` emits array paths, including paths that do not yet exist when the expression is exact. `paths` enumerates non-root paths, optionally filtered by a value predicate. `getpath` reads one or more paths and returns null for absent values where jq specifies that behavior.

Object keys are strings and array indexes are numbers. Path traversal preserves generator order, supports nested arrays and objects, and enforces the implementation's path-depth limit.

## Programmatic Acceptance

Intent: The authoritative corpus executes the path, paths, and getpath cases owned by this story.
Suite: scoped
Requires: executable=python3; scope=test

    text=True,
    env={**os.environ, "JQ": f"{os.getcwd()}/jq"},

print(result.stdout)
print(result.stderr, file=sys.stderr)
report = json.loads(result.stdout)
summary = report["summary"]
assert sum(summary.values()) > 0
assert summary["fail"] == 0 and summary["error"] == 0
assert result.returncode == 0
=== END AC paths-discovery-suite ===

## User Acceptance

- None.

## Guardrails

- Do not mutate the input while discovering or reading paths.
- Preserve path ordering and generator multiplicity.
- Do not treat the root path as a member of `paths`.
- Do not resolve excluded module-loader cases through filesystem access.

# FEATURE: Paths Mutation

| Field       | Value |
|-------------|-------|
| Version     | 20260820 V1 |
| Description | Set and delete values immutably through jq paths. |
| Depends On  | FEATURE-Paths-Discovery.md |
| Provides    | setpath, delpaths, del |
| Consumes    | path, paths, getpath, immutable value construction |

## Questions

- None.

## Capability

Path mutation creates a new jq value from the input. `setpath` creates missing object and array containers as required, replaces existing values, grows arrays with nulls, and rejects invalid path components. `delpaths` removes the specified paths while preserving the remaining structure. `del` converts a path expression into deletions and supports multiple paths, slices, and empty path streams.

Operations must preserve immutable assignment semantics, support null and absent intermediate values, retain ordering-independent structural equality, and enforce path-depth limits. Invalid paths and excessive depth raise runtime errors with exit status 5 when uncaught.

- Depth limits must prevent runaway path construction.

# FEATURE: Paths Assignment

| Field       | Value |
|-------------|-------|
| Version     | 20260820 V1 |
| Description | Apply jq plain, update, arithmetic, and defined-or assignments over paths. |
| Depends On  | FEATURE-Paths-Mutation.md |
| Provides    | =, |=, +=, -=, *=, /=, %=, //= |
| Consumes    | path mutation, generator evaluation, runtime errors, bindings |

## Questions

- None.

## Capability

Assignment evaluates left-hand sides as path expressions over the original input and produces immutable replacement values. Plain assignment uses the original input as the right-hand-side input and emits one result per right-hand-side value. Update assignment evaluates its right-hand side against each selected path and uses only the first result; an empty result deletes the path.

Arithmetic update operators expand to update assignment with the corresponding binary operator. Defined-or assignment updates only false or null values. Multiple paths, slices, generator-valued right-hand sides, nested assignments, and partial runtime output follow jq ordering and backtracking semantics.

# FEATURE: Control Conditionals

| Field       | Value |
|-------------|-------|
| Version     | 20260820 V1 |
| Description | Implement jq conditionals, boolean filters, lexical labels, and breaks. |
| Depends On  | FEATURE-Core-Errors.md, FEATURE-Paths-Assignment.md |
| Provides    | if, then, elif, else, end, label, break, and, or, not |
| Consumes    | runtime error handling, generator evaluation, assignment, bindings |

## Questions

- None.

## Capability

Conditional expressions evaluate each result of their condition independently. Only false and null are falsey; every other jq value is truthy. `elif` chains and omitted `else` branches follow jq's identity behavior.

`and` and `or` produce boolean results for each relevant operand combination. `not` negates jq truthiness. Labels establish lexical break targets, and `break $label` terminates the nearest visible labeled computation with empty output from that label. Unbound or lexically invisible labels are compile errors.

# FEATURE: Control Reductions

| Field       | Value |
|-------------|-------|
| Version     | 20260820 V1 |
| Description | Accumulate ordered generator streams with reduce and foreach. |
| Depends On  | FEATURE-Control-Conditionals.md |
| Provides    | reduce, foreach |
| Consumes    | ordered generators, bindings, patterns, conditionals, lexical breaks |

## Questions

- None.

## Capability

`reduce EXP as $var (INIT; UPDATE)` evaluates every output of `EXP` in order, binds each output or pattern match, applies `UPDATE` to the accumulator, and emits the resulting accumulator stream. Multiple initial values and generator-valued expressions preserve jq's cartesian and backtracking semantics.

`foreach EXP as $var (INIT; UPDATE; EXTRACT)` exposes each intermediate accumulator to `EXTRACT`; when extraction is omitted it emits the intermediate accumulator itself. Pattern bindings, multiple outputs, lexical breaks, and runtime errors must preserve partial output behavior and ordering.

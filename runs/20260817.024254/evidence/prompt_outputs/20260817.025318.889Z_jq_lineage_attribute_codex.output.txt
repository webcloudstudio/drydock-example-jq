<requirement name="filter-language-basics" stories="frontend-002">
A jq program is a "filter": it takes an input, and produces an output.
</requirement>
<requirement name="lexical-comments" stories="frontend-001">
You can write comments in your jq filters using `#`.
</requirement>
<requirement name="lexical-bindings-functions-modules" stories="frontend-003">
It is also possible to define functions in jq, although this
is is a feature whose biggest use is defining jq's standard library
(many jq functions such as `map` and `select` are in fact written
in jq).
</requirement>
<requirement name="generator-evaluation" stories="eval-001">
Some jq operators and functions are actually generators in
that they can produce zero, one, or more values for each
input, just as one might expect in other programming
languages that have generators.
</requirement>
<requirement name="operators-conditionals" stories="eval-002">
jq supports the normal Boolean operators `and`, `or`, `not`.
</requirement>
<requirement name="generator-control-constructs" stories="eval-003">
The `reduce` syntax allows you to combine all of the results of
an expression by accumulating them into a single answer.
</requirement>
<requirement name="json-values-and-structures" stories="data-001">
jq supports the same set of datatypes as JSON - numbers,
strings, booleans, arrays, objects (which in JSON-speak are
hashes with only string keys), and "null".
</requirement>
<requirement name="paths-and-mutation-primitives" stories="data-002">
The builtin function `path` outputs array representations of the given path expression
in `.`.
</requirement>
<requirement name="immutable-assignment" stories="data-003">
Values in jq are always immutable.
</requirement>
<requirement name="collection-builtins" stories="builtin-001">
For any filter `f`, `map(f)` and `map_values(f)` apply `f`
to each of the values in the input array or object, that is,
to the values of `.[]`.
</requirement>
<requirement name="string-unicode-builtins" stories="builtin-002">
jq provides builtins for manipulating strings and Unicode text.
</requirement>
<requirement name="regular-expression-builtins" stories="builtin-003">
jq uses the
[Oniguruma regular expression library](https://github.com/kkos/oniguruma/blob/master/doc/RE),
as do PHP, TextMate, Sublime Text, etc, so the description here will focus on jq specifics.
</requirement>
<requirement name="format-date-math-environment-builtins" stories="builtin-004">
jq provides some basic date handling functionality, with some
high-level and low-level builtins.
</requirement>
<requirement name="streaming-io-and-sql-builtins" stories="builtin-005">
At this time jq has minimal support for I/O, mostly in the
form of control over when inputs are read.
</requirement>

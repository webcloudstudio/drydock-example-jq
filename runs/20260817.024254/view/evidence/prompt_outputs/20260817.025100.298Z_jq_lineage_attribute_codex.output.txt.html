<requirement name="define-evaluation-model" stories="architecture,eval-001">
jq is a small language with a large semantic core. Almost every filter is a **generator**: it takes one input and produces a stream of zero, one, or many outputs, and downstream filters run once per upstream output. Backtracking through that stream is not an optimisation, it is the evaluation model, and `reduce`, `foreach`, `limit`, `first`, `label`/`break`, and the `?//` destructuring alternative are all defined in terms of it. An implementation that treats a filter as a function returning one value will pass the early cases and then stall permanently. Decide the evaluation model before writing builtins.
</requirement>

<article class="doc"><h1>ARCHITECTURE: jq Interpreter</h1>
<div class="scroll"><table><thead><tr><th>Field</th><th>Value</th></tr></thead><tbody><tr><td>Version</td><td>20260822 V1</td></tr><tr><td>Description</td><td>Standard-library Python architecture for a standalone jq interpreter.</td></tr><tr><td>Depends On</td><td>COMPASS.md, TECHNOLOGY_STACK.md</td></tr><tr><td>Provides</td><td>jq interpreter architecture, executable boundary, parser, evaluator, runtime</td></tr><tr><td>Consumes</td><td>—</td></tr></tbody></table></div>
<h2>System Overview</h2>
<p>The application is an executable named <code>jq</code> at the application root. It accepts <code>-c &#x27;&lt;program&gt;&#x27;</code>, reads JSON values from standard input, evaluates the jq program as an ordered generator, and writes compact JSON values one per line.</p>
<p>The implementation is composed of:</p>
<ul><li>CLI and process boundary.</li><li>Lexer and recursive-descent or precedence parser.</li><li>AST and compiled filter representation.</li><li>Generator evaluator with lexical environments.</li><li>jq value, numeric, accessor, assignment, builtin, and runtime-error layers.</li><li>Streaming JSON input and output serialization.</li></ul>
<p>All runtime code uses Python 3.11+ standard-library modules only. The implementation must not invoke, import, or bind to another jq implementation.</p>
<h2>Module Boundaries</h2>
<div class="scroll"><table><thead><tr><th>Module</th><th>Responsibility</th></tr></thead><tbody><tr><td><code>jq</code></td><td>Executable entry point and command-line validation</td></tr><tr><td><code>jq_runtime.py</code> or equivalent</td><td>Input stream, evaluation context, errors, output serialization</td></tr><tr><td><code>jq_lexer.py</code> or equivalent</td><td>Tokens, comments, literals, strings, interpolation markers</td></tr><tr><td><code>jq_parser.py</code> or equivalent</td><td>AST construction, precedence, declarations, syntax validation</td></tr><tr><td><code>jq_eval.py</code> or equivalent</td><td>Ordered generator evaluation, environments, functions, control flow</td></tr><tr><td><code>jq_values.py</code> or equivalent</td><td>jq values, numeric handling, comparison, access, mutation</td></tr><tr><td><code>jq_builtins.py</code> or equivalent</td><td>Builtin filters and standard-library implementations</td></tr></tbody></table></div>
<p>The concrete module filenames may vary, but responsibilities remain isolated at these boundaries.</p>
<h2>Evaluation Model</h2>
<p>Every filter receives one input and yields an ordered stream of zero or more outputs. Pipes evaluate the right-hand filter once per left-hand output. Commas concatenate streams. Filter arguments remain generators, while value arguments are evaluated and bound as values. Runtime errors propagate through the stream and preserve outputs already emitted.</p>
<p>Assignments operate immutably over paths and return replacement values rather than mutating shared input objects.</p>
<h2>Process Contract</h2>
<ul><li>Compile success and complete execution exit <code>0</code>.</li><li>Compile or static failure exit <code>3</code>.</li><li>Runtime failure exit <code>5</code>.</li><li>Diagnostics are written to standard error.</li><li>Output is compact JSON, one generated value per line.</li><li>Partial output before a runtime failure is preserved.</li></ul>
<h2>Technology Stack</h2>
<div class="scroll"><table><thead><tr><th>Technology</th><th>Application</th></tr></thead><tbody><tr><td>Python</td><td>Interpreter, parser, evaluator, builtins, CLI</td></tr><tr><td>POSIX sh</td><td>Supplied conformance entry point</td></tr></tbody></table></div>
<p>Only Python standard-library facilities are permitted at runtime.</p>
<h2>Source and Test Asset Boundary</h2>
<p>The supplied files under <code>sources/</code> are immutable inputs. The implementation reads them when required but does not modify them. The conformance runner is external to the interpreter and remains the authority for corpus comparison.</p>

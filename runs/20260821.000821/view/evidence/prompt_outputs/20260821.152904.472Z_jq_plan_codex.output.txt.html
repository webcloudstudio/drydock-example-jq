# ARCHITECTURE: jq Interpreter

## Questions

- None.

## Purpose

The application is a standalone executable named `jq` at the application root. It accepts `-c` and a jq filter, reads JSON values from standard input, evaluates the filter as an ordered generator, and writes compact JSON outputs one per line.

## Module Boundaries

| Module | Responsibility |
|---|---|
| CLI | Argument validation, JSON input framing, output serialization, exit-code mapping |
| Lexer | jq tokens, strings, interpolation, comments, operators, delimiters |
| Parser | Precedence-aware grammar and AST construction |
| Compiler | Static validation, binding resolution, function definitions, labels |
| Evaluator | Generator execution, streams, backtracking, control flow, runtime errors |
| Values | JSON-compatible immutable values, numeric semantics, structural comparison |
| Paths | Path discovery, access, immutable updates, deletion, assignments |
| Builtins | jq-defined functions and standard-library behavior |
| Harness boundary | No runtime dependence on external jq or third-party packages |

## Evaluation Model

Every filter receives one input value and yields zero or more output values. Pipes execute the right-hand filter once for every left-hand output. Commas concatenate streams in source order. Collection constructors consume all outputs, while runtime errors preserve outputs already emitted.

## Error Contract

Compile and static errors return exit code `3`. Runtime errors return exit code `5`, after preserving any values already written. Successful completion returns `0`. Diagnostics are written only to standard error.

## Technology Stack

- Python 3.11 or newer, standard library only.
- POSIX `sh` for the supplied conformance entry point.
- No network access, package installation, third-party jq implementation, or system jq delegation.

## Source Policy

Files under `sources/` are staged supplied assets. The implementation reads them as specifications or scoring inputs and never modifies them. The conformance corpus and harness remain authoritative for behavioral correctness.

| Field       | Value |
|-------------|-------|

| Depends On  | FEATURE-FOUNDATION-001.md |
| Provides    | `./jq -c '<program>'`, stdin JSON input, compact JSON output, exit codes 0/3/5 |
| Consumes    | staged jq corpus and interpreter runtime |

## Questions

- None.

## Interface

The executable accepts `-c` followed by a jq program. It reads JSON values from standard input, evaluates each value, writes each generated result as one compact JSON value per line, and writes diagnostics to standard error.

Exit codes:

- `0`: compilation and execution completed.
- `3`: the program did not compile.
- `5`: the program compiled but raised at runtime.

Values emitted before a runtime error remain on standard output.

## Programmatic Acceptance

    ["./jq", "-c", "."],
    input=payload,
    capture_output=True,
    text=True,
    env={**os.environ},
)

assert actual == values

## Questions

- None.

## Scope

The lexer recognizes:

- identifiers, field selectors, variable bindings, and module-qualified names;
- JSON-compatible numeric and string literals;
- string interpolation and format tokens;
- keywords including `def`, `if`, `try`, `reduce`, `foreach`, `label`, `import`, and `include`;
- arithmetic, comparison, assignment, defined-or, alternation, and stream operators;
- brackets, braces, parentheses, comments, whitespace, and invalid characters.

Lexical errors must be surfaced to the compiler so the executable returns exit code `3`.

## Programmatic Acceptance

import json
import os
import subprocess
import sys

selector = r'^(\\.|\\[|\\{|def|if|try|reduce|foreach|module|include|%::|"|@)'
result = subprocess.run(
    [sys.executable, "sources/run_conformance.py", "--select", selector, "--json"],
    capture_output=True,

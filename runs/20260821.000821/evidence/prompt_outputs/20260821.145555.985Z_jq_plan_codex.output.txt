# FEATURE: jq Expression Parser

| Field       | Value |
|-------------|-------|
| Version     | 20260821 V1 |
| Description | Define the jq parser and abstract syntax tree for valid expressions. |
| Depends On  | ARCHITECTURE.md, FEATURE-Lexer.md |
| Provides    | parser, AST, precedence, expressions, constructors |
| Consumes    | lexer, sources/parser.y |

## Questions

- None.

## Scope

The parser consumes lexer tokens and produces an AST representing jq programs. It must preserve the precedence and associativity defined by `sources/parser.y`, including pipelines, generators, operators, suffix access, arrays, objects, conditionals, function calls, bindings, and assignments.

The AST must retain enough structure for downstream evaluation, static validation, generator semantics, path expressions, and runtime diagnostics.

## Programmatic Acceptance

=== AC parser-conformance ===
Intent: The parser accepts the non-empty corpus slice covering parser-led jq constructs and the selected cases execute successfully.
Suite: scoped
Requires: executable=python3; scope=test

import json
import os
import subprocess
import sys

selector = r'^(\.|\[|\{|\{|\(|def|if|try|reduce|foreach|module|include|%::|"|@)'
result = subprocess.run(
    [sys.executable, "sources/run_conformance.py", "--select", selector, "--json"],
    capture_output=True,
    text=True,
    env={**os.environ, "JQ": f"{os.getcwd()}/jq"},
)
print(result.stdout)
print(result.stderr, file=sys.stderr)
report = json.loads(result.stdout)
summary = report["summary"]
assert sum(summary.values()) > 0
assert summary["fail"] == 0
assert summary["error"] == 0
assert result.returncode == 0
=== END AC parser-conformance ===

Compilation validates syntax and statically resolvable symbols after parsing. Invalid object keys, malformed expressions, undefined variables or labels, invalid module metadata, and unsupported module grammar must produce diagnostics on standard error and exit status `3`.

## Scope

Function definitions support zero or more filter parameters and value parameters, lexical visibility, closures, recursion, arity, and redefinition. Function arguments are filters unless declared as value bindings. Definitions become visible according to jq's left-to-right lexical rules.

# FEATURE: jq Destructuring and Alternatives

| Field       | Value |
|-------------|-------|
| Version     | 20260821 V1 |
| Description | Implement jq array and object destructuring with alternative-pattern backtracking. |
| Depends On  | ARCHITECTURE.md, FEATURE-Functions-and-Scope.md |
| Provides    | array patterns, object patterns, missing bindings, ?// alternatives |
| Consumes    | parser, AST, ordered filter streams |

## Questions

- None.

## Scope

Destructuring binds array positions and object members to lexical variables. Missing array positions and object members bind to `null`. Nested patterns compose across arrays and objects.

The `?//` operator retries later patterns when an earlier pattern fails or downstream evaluation raises, retaining the bindings from the successful alternative and setting unavailable bindings to `null`.

# FEATURE: jq Generator Evaluation Core

| Field       | Value |
|-------------|-------|
| Version     | 20260821 V1 |
| Description | Evaluate every jq filter as an ordered zero-or-more value stream. |
| Depends On  | ARCHITECTURE.md, FEATURE-Parser.md |
| Provides    | ordered filter streams, backtracking, multiplicity, empty |
| Consumes    | parser, AST |

## Questions

- None.

## Scope

The evaluator represents each filter as a generator of zero or more values. Comma concatenates streams in source order; pipe evaluates its right side once for every left-side output; expressions with multiple outputs preserve cartesian products. `empty` produces no values and backtracking resumes the preceding generator.

Runtime errors may occur after earlier values have been emitted; those values remain observable.

# ARCHITECTURE: jq Interpreter

| Field       | Value |
|-------------|-------|
| Version     | 20260821 V1 |
| Description | Defines the standalone standard-library Python architecture for the jq interpreter. |
| Depends On  | sources/jq-manual.txt, sources/parser.y, sources/lexer.l, TECHNOLOGY_STACK.md |
| Provides    | lexer, parser, AST, stream evaluator, path engine, builtin registry, jq CLI |
| Consumes    | stdin JSON stream, jq filter program, staged conformance assets |

## Questions

- None.

## Purpose

The application is a standalone executable named `jq` at the application root. It accepts `-c` and a jq filter, reads JSON values from standard input, evaluates the filter as an ordered generator, and writes compact JSON outputs one per line.

## Module Boundaries

| Module | Responsibility |
|---|---|
| CLI | Argument validation, JSON input framing, output serialization, exit-code mapping |
| Lexer | jq tokens, strings, interpolation, comments, operators, delimiters |
| Parser | Precedence-aware grammar and AST construction |
| Compiler | Static validation, binding resolution, function definitions, labels |
| Evaluator | Generator execution, streams, backtracking, control flow, runtime errors |
| Values | JSON-compatible immutable values, numeric semantics, structural comparison |
| Paths | Path discovery, access, immutable updates, deletion, assignments |
| Builtins | jq-defined functions and standard-library behavior |
| Harness boundary | No runtime dependence on external jq or third-party packages |

## Evaluation Model

Every filter receives one input value and yields zero or more output values. Pipes execute the right-hand filter once for every left-hand output. Commas concatenate streams in source order. Collection constructors consume all outputs, while runtime errors preserve outputs already emitted.

## Error Contract

Compile and static errors return exit code `3`. Runtime errors return exit code `5`, after preserving any values already written. Successful completion returns `0`. Diagnostics are written only to standard error.

## Technology Stack

- Python 3.11 or newer, standard library only.
- POSIX `sh` for the supplied conformance entry point.
- No network access, package installation, third-party jq implementation, or system jq delegation.

## Source Policy

Files under `sources/` are staged supplied assets. The implementation reads them as specifications or scoring inputs and never modifies them. The conformance corpus and harness remain authoritative for behavioral correctness.

# FEATURE: jq Executable Boundary

| Field       | Value |
|-------------|-------|
| Version     | 20260821 V1 |
| Description | Provides the executable jq command-line and JSON stream contract. |
| Depends On  | FEATURE-FOUNDATION-001.md |
| Provides    | `./jq -c '<program>'`, stdin JSON input, compact JSON output, exit codes 0/3/5 |
| Consumes    | staged jq corpus and interpreter runtime |

## Questions

- None.

## Interface

The executable accepts `-c` followed by a jq program. It reads JSON values from standard input, evaluates each value, writes each generated result as one compact JSON value per line, and writes diagnostics to standard error.

Exit codes:

- `0`: compilation and execution completed.
- `3`: the program did not compile.
- `5`: the program compiled but raised at runtime.

Values emitted before a runtime error remain on standard output.

## Programmatic Acceptance

=== AC cli-success ===
Intent: The executable accepts the required option and round-trips supplied JSON values.

import json
import os
import subprocess

values = [{"a": 1}, [1, 2], None]
payload = "\n".join(json.dumps(value) for value in values) + "\n"
result = subprocess.run(
    ["./jq", "-c", "."],
    input=payload,
    capture_output=True,
    text=True,
    env={**os.environ},
)
assert result.returncode == 0
actual = [json.loads(line) for line in result.stdout.splitlines()]
assert actual == values
=== END AC cli-success ===

=== AC cli-compile-error ===
Intent: A syntactically invalid jq program returns the documented compile-failure status.

import os
import subprocess

result = subprocess.run(
    ["./jq", "-c", "{"],
    input="null\n",
    capture_output=True,
    text=True,
    env={**os.environ},
)
assert result.returncode == 3
=== END AC cli-compile-error ===

=== AC cli-runtime-error ===
Intent: A compiled runtime error returns status 5 while preserving prior generated output.

import json
import os
import subprocess

result = subprocess.run(
    ["./jq", "-c", "1, error"],
    input="null\n",
    capture_output=True,
    text=True,
    env={**os.environ},
)
assert result.returncode == 5
assert [json.loads(line) for line in result.stdout.splitlines()] == [1]
=== END AC cli-runtime-error ===

## User Acceptance

- None.

## Guardrails

- Implement only the exercised `-c` interface.
- Never delegate evaluation to a system jq executable.
- Preserve output generated before runtime failure.
- Keep diagnostics off standard output.

# FEATURE: jq Lexical Scanner

| Field       | Value |
|-------------|-------|
| Version     | 20260821 V1 |
| Description | Tokenizes jq programs according to the supplied lexer specification. |
| Depends On  | FEATURE-FOUNDATION-002.md |
| Provides    | jq lexer tokens for identifiers, bindings, literals, strings, interpolation, formats, operators, delimiters, comments, and invalid characters |
| Consumes    | sources/lexer.l, sources/jq-manual.txt |

## Questions

- None.

## Scope

The lexer recognizes:

- identifiers, field selectors, variable bindings, and module-qualified names;
- JSON-compatible numeric and string literals;
- string interpolation and format tokens;
- keywords including `def`, `if`, `try`, `reduce`, `foreach`, `label`, `import`, and `include`;
- arithmetic, comparison, assignment, defined-or, alternation, and stream operators;
- brackets, braces, parentheses, comments, whitespace, and invalid characters.

Lexical errors must be surfaced to the compiler so the executable returns exit code `3`.

## Programmatic Acceptance

=== AC lexer-conformance ===
Intent: The executable passes the non-empty corpus slice selected by the lexical syntax families.

import json
import os
import subprocess
import sys

selector = r'^(\\.|\\[|\\{|def|if|try|reduce|foreach|module|include|%::|"|@)'
result = subprocess.run(
    [sys.executable, "sources/run_conformance.py", "--select", selector, "--json"],
    capture_output=True,
    text=True,
    env={**os.environ, "JQ": f"{os.getcwd()}/jq"},
)
print(result.stdout)
print(result.stderr, file=sys.stderr)
report = json.loads(result.stdout)
tally = report["summary"]
assert sum(tally.values()) > 0
assert tally["fail"] == 0 and tally["error"] == 0
assert result.returncode == 0
=== END AC lexer-conformance ===

=== AC lexer-invalid-program ===
Intent: Invalid lexical characters are rejected with compile status 3.

import os
import subprocess

result = subprocess.run(
    ["./jq", "-c", "@"],
    input="null\n",
    capture_output=True,
    text=True,
    env={**os.environ},
)
assert result.returncode == 3
=== END AC lexer-invalid-program ===

=== AC lexer-comment-and-format ===
Intent: The scanner accepts comments and format tokens in a valid jq program.

import json
import os
import subprocess

program = '@text # comment\n'
input_value = "hello"
result = subprocess.run(
    ["./jq", "-c", program],

    capture_output=True,
    text=True,
    env={**os.environ},
)
assert result.returncode == 0
assert json.loads(result.stdout) == input_value
=== END AC lexer-comment-and-format ===

- None.

## Guardrails

- Follow `sources/lexer.l` for token boundaries and escape handling.
- Preserve Unicode strings and interpolation boundaries.
- Reject invalid characters rather than silently dropping them.
- Keep lexical compilation failures distinct from runtime failures.

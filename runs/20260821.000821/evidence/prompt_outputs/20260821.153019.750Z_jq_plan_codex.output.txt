# FEATURE: Frontend Expression Parser

| Field       | Value |
|-------------|-------|
| Version     | 20260821 V1 |
| Description | Defines the jq expression parser and abstract syntax tree forms. |
| Depends On  | FEATURE-FRONTEND-001.md |
| Provides    | jq expression AST, precedence handling, constructor parsing, assignment parsing |
| Consumes    | jq lexical tokens |

## Questions

- None.

## Purpose

Implement the jq parser and AST construction layer from `sources/parser.y`. The parser must preserve jq precedence and associativity and represent expressions for evaluation by later runtime stories.

## Scope

The parser covers:

- operator precedence, associativity, and grouping;
- suffix access, indexing, iteration, slices, and optional operators;
- literals, strings, interpolation, arrays, and objects;
- conditionals, errors, reductions, bindings, functions, assignments, and module grammar;
- AST nodes retaining generator structure and source locations where required.

The parser must reject malformed syntax through the compile-time error boundary supplied by the executable story.

## Programmatic Acceptance

=== AC frontend-002-conformance ===
Intent: The parser passes every selected corpus case exercising expression, constructor, control, string, and module syntax.
Suite: scoped
Requires: executable=python3; scope=test

import json
import os
import subprocess
import sys

selector = r"^(\.|\[|\{|def|if|try|reduce|foreach|module|include|%::|\"|@)"
result = subprocess.run(
    [sys.executable, "sources/run_conformance.py", "--select", selector, "--json"],
    capture_output=True,
    text=True,
    env={**os.environ, "JQ": f"{os.getcwd()}/jq"},
)
print(result.stdout)
print(result.stderr, file=sys.stderr)
report = json.loads(result.stdout)
summary = report["summary"]
assert sum(summary.values()) > 0
assert summary["fail"] == 0
assert summary["error"] == 0
assert result.returncode == 0
=== END AC frontend-002-conformance ===

## User Acceptance

- None.

## Guardrails

- Preserve generator-oriented AST structure.
- Use only the standard library implementation defined by the project architecture.
- Do not modify supplied parser, lexer, corpus, or harness assets.

# FEATURE: Core Stream Evaluation

| Field       | Value |
|-------------|-------|
| Version     | 20260821 V1 |
| Description | Defines jq's ordered zero-or-more-value generator evaluation model. |
| Depends On  | FEATURE-FRONTEND-003.md |
| Provides    | Stream evaluator, pipeline backtracking, generator ordering, empty stream |
| Consumes    | Parsed jq AST, immutable JSON values |

## Questions

- None.

## Purpose

Build the evaluator around jq's generator model: every filter consumes one input and produces an ordered stream of zero or more outputs.

## Scope

The evaluator must support downstream execution for every upstream result, cartesian evaluation of multi-output expressions, comma concatenation, pipeline backtracking, multiplicity, empty-stream propagation, and preservation of values emitted before a runtime error.

This story establishes the execution protocol used by all later filters and builtins; it does not own the complete syntax or builtin surface.

## Programmatic Acceptance

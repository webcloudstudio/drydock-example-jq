| Field       | Value |
|-------------|-------|
| Version     | 20260821 V1 |

| Depends On  | — |
| Provides    | interpreter architecture, evaluator boundaries, CLI contract |
| Consumes    | sources/jq-manual.txt, sources/parser.y, sources/lexer.l |

## Questions

- None.

## System Boundary

The executable `jq` accepts `-c PROGRAM`, reads JSON values from standard input, evaluates the program as an ordered jq generator, and writes compact JSON values to standard output, one per line.

## Module Boundaries

- `cli`: argument parsing, JSON input decoding, output serialization, diagnostics, and exit codes.
- `lexer`: jq tokenization, comments, literals, strings, interpolation, formats, and delimiters.
- `parser`: precedence-aware parsing into an AST and compile-time validation.
- `runtime`: generator evaluation, lexical environments, control flow, errors, and labels.
- `values`: native Python JSON-compatible values, numeric handling, structural equality, and ordering.
- `paths`: path discovery, reads, immutable updates, deletion, and assignment.
- `builtins`: jq-defined and Python-implemented builtin filters.
- `sources`: read-only conformance and normative assets.

Evaluation is stream-based: every filter receives one input and yields zero or more outputs. Pipes evaluate downstream filters once per upstream output; commas preserve left-to-right ordering; runtime errors retain output already emitted.

## Technology Stack

- Python 3.11 or newer, standard library only.
- POSIX `sh` for the supplied verification entry point.

## Constraints and Interfaces

The implementation must not invoke a system jq, import a third-party jq implementation, access the network, install packages, or modify files under `sources/`. Compile failures exit `3`; runtime failures exit `5`; successful completion exits `0`.

# FEATURE: Executable Contract

| Field       | Value |
|-------------|-------|
| Version     | 20260821 V1 |
| Description | Defines the jq executable's command-line, JSON stream, output, and exit-code contract. |
| Depends On  | ARCHITECTURE.md, FEATURE-Foundation-Assets.md |
| Provides    | ./jq, -c CLI, JSON stdin stream, compact JSON stdout stream, exit codes 0/3/5 |
| Consumes    | ARCHITECTURE.md |

## Questions

- None.

## Interface

The executable is invoked as `./jq -c PROGRAM`. It reads one or more JSON values from standard input and emits every generated result as one compact JSON value per line. Diagnostics go to standard error.

A valid program that completes exits `0`. A program that fails compilation exits `3`. A program that raises during evaluation exits `5`, while retaining values emitted before the error.

## Programmatic Acceptance

=== AC cli-valid-stream ===
Intent: The executable accepts -c, processes multiple JSON inputs, and emits one compact result per input.

import json
import os
import subprocess

program = "."
values = [{"a": 1}, [2, 3]]
payload = "".join(json.dumps(value) + "\n" for value in values)
result = subprocess.run(
    ["./jq", "-c", program],
    input=payload,
    capture_output=True,
    text=True,
    env={**os.environ},
)
assert result.returncode == 0
actual = [json.loads(line) for line in result.stdout.splitlines()]
assert actual == values
=== END AC cli-valid-stream ===

=== AC cli-compile-error ===
Intent: A syntactically invalid jq program returns the documented compile-failure status.

import os
import subprocess

program = "{"
result = subprocess.run(
    ["./jq", "-c", program],
    input="null\n",
    capture_output=True,
    text=True,
    env={**os.environ},
)
assert result.returncode == 3
=== END AC cli-compile-error ===

=== AC cli-runtime-error ===
Intent: A runtime failure returns status 5 after preserving values emitted before the failure.

import json
import os
import subprocess

program = "1, error"
result = subprocess.run(
    ["./jq", "-c", program],
    input="null\n",
    capture_output=True,
    text=True,
    env={**os.environ},
)
assert result.returncode == 5
actual = [json.loads(line) for line in result.stdout.splitlines()]
expected = [1]
assert actual == expected
=== END AC cli-runtime-error ===

## User Acceptance

- None.

## Guardrails

- Only `-c` is required and exercised.
- Diagnostics must remain on stderr.
- Do not shell out to a system jq executable.

# FEATURE: Lexer

| Field       | Value |
|-------------|-------|
| Version     | 20260821 V1 |

| Depends On  | ARCHITECTURE.md |
| Provides    | lexer, tokens, literals, interpolation, comments, formats, delimiters |
| Consumes    | ARCHITECTURE.md, sources/lexer.l |

## Questions

- None.

## Scope

The lexer recognizes identifiers, field names, variable bindings, numeric and string literals, interpolation delimiters, format tokens, comments, keywords, operators, brackets, braces, parentheses, whitespace, and invalid characters. String escapes are validated as JSON-compatible escapes, and comments follow jq's continuation rules.

## Programmatic Acceptance

=== AC lexer-scoped-conformance ===
Intent: The lexer implementation passes the non-empty corpus slice covering literals, strings, formats, delimiters, and core lexical forms.

import json
import os
import subprocess
import sys

select = r'^(\\.|\\[|\\{|def|if|try|reduce|foreach|module|include|%::|"|@)'
result = subprocess.run(
    [sys.executable, "sources/run_conformance.py", "--select", select, "--json"],
    capture_output=True,
    text=True,
    env={**os.environ, "JQ": f"{os.getcwd()}/jq"},
)
print(result.stdout)
print(result.stderr, file=sys.stderr)
report = json.loads(result.stdout)
tally = report["summary"]
assert sum(tally.values()) > 0
assert tally["fail"] == 0
assert tally["error"] == 0
assert result.returncode == 0
=== END AC lexer-scoped-conformance ===

=== AC lexer-invalid-character ===
Intent: Invalid lexical input is rejected with compile exit status 3.

=== END AC lexer-invalid-character ===

# FEATURE: Values Model

| Field       | Value |
|-------------|-------|
| Version     | 20260816 V1 |
| Description | Define jq's JSON-compatible value model, numeric behavior, and compact serialization. |
| Depends On  | ARCHITECTURE.md, FEATURE-Eval-Core.md |
| Provides    | JSON value model and serialization |
| Consumes    | ordered generator evaluator |

## Questions

- None.

## Intent

The runtime represents null, booleans, strings, arrays, objects, numbers, NaN, and infinities using Python standard-library facilities. JSON input is parsed as a sequence of values, and results are serialized as compact JSON lines. Literal numeric spelling is preserved where jq semantics require it; arithmetic follows jq-compatible floating-point behavior.

## Behavior

- Preserve JSON structural types without conflating booleans and numbers.
- Support Unicode strings, embedded NULs, NaN, and infinities.
- Serialize each output compactly and emit one value per line.
- Parse multiple JSON inputs from standard input.
- Ensure serialization never emits non-JSON NaN or infinity tokens where jq emits `null`.

## Programmatic Acceptance

=== AC values-model-roundtrip ===
Intent: JSON values supplied as input are emitted with the same structure and type distinctions.
import json
import subprocess

value = {"null": None, "bool": True, "number": 7, "text": "a\u0000b", "array": [1, False]}
result = subprocess.run(
    ["./jq", "-c", "."],
    input=json.dumps(value) + "\n",
    capture_output=True,
    text=True,
)
assert result.returncode == 0
actual = json.loads(result.stdout)
assert actual == value
assert isinstance(actual["bool"], bool)
assert not isinstance(actual["number"], bool)
=== END AC values-model-roundtrip ===

=== AC values-model-multiple-inputs ===
Intent: Multiple JSON input values produce an ordered output stream.
import json
import subprocess

inputs = [None, True, {"x": 1}]
payload = "\n".join(json.dumps(item) for item in inputs) + "\n"
result = subprocess.run(
    ["./jq", "-c", "."],
    input=payload,
    capture_output=True,
    text=True,
)
assert result.returncode == 0
actual = [json.loads(line) for line in result.stdout.splitlines()]
assert actual == inputs
=== END AC values-model-multiple-inputs ===

=== AC values-model-compact-output ===
Intent: Compact output contains one complete JSON value per line.
import subprocess

value = {"items": [1, 2], "flag": True}
result = subprocess.run(
    ["./jq", "-c", "."],
    input='{"items":[1,2],"flag":true}\n',
    capture_output=True,
    text=True,
)
assert result.returncode == 0
lines = result.stdout.splitlines()
assert len(lines) == 1
assert "\n" not in lines[0]
assert " " not in lines[0]
=== END AC values-model-compact-output ===

## User Acceptance

- None.

## Guardrails

- Do not use third-party runtime packages or delegate evaluation to another jq implementation.
- Preserve the distinction between booleans and numbers.
- Do not alter supplied corpus or harness assets.

# FEATURE: Values Arithmetic

| Field       | Value |
|-------------|-------|
| Version     | 20260816 V1 |
| Description | Implement jq arithmetic, type-dependent operators, and recursive object merging. |
| Depends On  | FEATURE-Values-Model.md, FEATURE-Eval-Cartesian.md |
| Provides    | arithmetic, merge, string, and array operators |
| Consumes    | JSON value model, evaluator |

## Questions

- None.

## Intent

Arithmetic operators evaluate operands as jq filters and apply type-dependent behavior. Numbers support arithmetic and modulo; arrays concatenate or subtract; strings concatenate, repeat, or split; objects merge shallowly with `+` and recursively with `*`; null acts as an identity for addition.

## Behavior

- Implement `+`, `-`, `*`, `/`, `%`, and unary negation.
- Implement array concatenation and subtraction.
- Implement string concatenation, repetition, and division.
- Implement shallow and recursive object merge.
- Raise runtime errors for invalid operand types and division by zero.

## Programmatic Acceptance

=== AC arithmetic-numeric ===
Intent: Numeric arithmetic and precedence produce the mathematically computed result.
import json
import subprocess

left = 7
right = 3
expected = [left + right, left - right, left * right, left / right, left % right]
program = "[\(left)+\(right), \(left)-\(right), \(left)*\(right), \(left)/\(right), \(left)%\(right)]"
result = subprocess.run(
    ["./jq", "-c", program],
    input="null\n",
    capture_output=True,
    text=True,
)
assert result.returncode == 0
actual = json.loads(result.stdout)
assert actual == expected
=== END AC arithmetic-numeric ===

=== AC arithmetic-composite ===
Intent: Composite values use jq's type-dependent addition and recursive multiplication.
source = '{"a":[1],"left":{"x":{"a":1}},"right":{"x":{"b":2}}}'
import json
import subprocess

program = "[.a + [2], .left * .right]"
result = subprocess.run(
    ["./jq", "-c", program],
    input=source + "\n",
    capture_output=True,
    text=True,
)
assert result.returncode == 0
actual = json.loads(result.stdout)
assert actual[0] == [1, 2]
assert actual[1]["x"] == {"a": 1, "b": 2}
=== END AC arithmetic-composite ===

=== AC arithmetic-errors ===
Intent: Division by zero is reported as a runtime failure.
import subprocess

result = subprocess.run(
    ["./jq", "-c", "1 / 0"],
    input="null\n",
    capture_output=True,
    text=True,
)
assert result.returncode == 5
=== END AC arithmetic-errors ===

## User Acceptance

- None.

## Guardrails

- Do not coerce unrelated jq types implicitly.
- Preserve outputs emitted before a later arithmetic runtime error.
- Use only standard-library numeric facilities.

# FEATURE: Values Comparison

| Field       | Value |
|-------------|-------|
| Version     | 20260816 V1 |
| Description | Implement jq structural comparison, ordering, boolean operators, and truthiness. |
| Depends On  | FEATURE-Values-Model.md, FEATURE-Eval-Cartesian.md |
| Provides    | equality, ordering, and boolean operators |
| Consumes    | JSON value model, evaluator |

## Questions

- None.

## Intent

Comparison follows jq's strict structural equality and total type ordering. Boolean operators evaluate filter streams and use only `false` and `null` as false values. The `not` filter returns the logical negation of jq truthiness.

## Behavior

- Implement `==` and `!=` without coercing strings, booleans, and numbers.
- Implement `<`, `<=`, `>`, and `>=` using jq type ordering.
- Implement `and`, `or`, and `not`.
- Evaluate multi-output operands in order.

## Programmatic Acceptance

=== AC comparison-structural ===
Intent: Equality distinguishes jq types while accepting structurally equal objects.
import json
import subprocess

program = '[1 == 1.0, true == 1, "1" == 1, {"a":1} == {"a":1}, {"a":1} != {"b":1}]'
result = subprocess.run(
    ["./jq", "-c", program],
    input="null\n",
    capture_output=True,
    text=True,
)
assert result.returncode == 0
actual = json.loads(result.stdout)
expected = [True, False, False, True, True]
assert actual == expected
=== END AC comparison-structural ===

=== AC comparison-ordering ===
Intent: Relational comparisons use numeric ordering and return booleans.
import json
import subprocess

low = 2
high = 5
program = f"[{low} < {high}, {low} <= {high}, {high} > {low}, {high} >= {high}]"
result = subprocess.run(
    ["./jq", "-c", program],
    input="null\n",
    capture_output=True,
    text=True,
)
assert result.returncode == 0
actual = json.loads(result.stdout)
assert actual == [low < high, low <= high, high > low, high >= high]
=== END AC comparison-ordering ===

=== AC comparison-truthiness ===
Intent: jq treats only false and null as false values.
import json
import subprocess

program = "[null|not, false|not, 0|not, \"\"|not, true|not]"
result = subprocess.run(
    ["./jq", "-c", program],
    input="null\n",
    capture_output=True,
    text=True,
)
assert result.returncode == 0
actual = json.loads(result.stdout)
assert actual == [True, True, False, False, False]
=== END AC comparison-truthiness ===

## User Acceptance

- None.

## Guardrails

- Never use Python truthiness in place of jq truthiness.
- Never equate booleans with numbers.
- Preserve jq's type ordering for heterogeneous values.

# FEATURE: Control Conditionals

| Field       | Value |
|-------------|-------|
| Version     | 20260816 V1 |
| Description | Implement jq conditionals, defined-or fallback, and optional expressions. |
| Depends On  | FEATURE-Values-Comparison.md, FEATURE-Eval-Cartesian.md |
| Provides    | if/then/elif/else/end, //, ? |
| Consumes    | evaluator, comparison operators |

## Questions

- None.

## Intent

Conditional expressions branch once for each condition result. `false` and `null` select the alternative branch; all other values select the then branch. The defined-or operator retains non-null, non-false generator results and otherwise evaluates its fallback. The optional operator suppresses runtime errors.

## Programmatic Acceptance

=== AC conditionals-branches ===
Intent: Conditional expressions select branches according to jq truthiness.
import json
import subprocess

program = '[if null then 1 elif false then 2 else 3 end, if 0 then 4 else 5 end, if "x" then 6 else 7 end]'
result = subprocess.run(
    ["./jq", "-c", program],
    input="null\n",
    capture_output=True,
    text=True,
)
assert result.returncode == 0
actual = json.loads(result.stdout)
assert actual == [3, 4, 6]
=== END AC conditionals-branches ===

=== AC conditionals-defined-or ===
Intent: Defined-or returns a defined left value and falls back for null or false.
import json
import subprocess

program = '[null // 9, false // 8, 0 // 7, (1, 2) // 6]'
result = subprocess.run(
    ["./jq", "-c", program],
    input="null\n",
    capture_output=True,
    text=True,
)
assert result.returncode == 0
actual = json.loads(result.stdout)
assert actual == [9, 8, 0, 1, 2]
=== END AC conditionals-defined-or ===

=== AC conditionals-optional ===
Intent: Optional expressions suppress indexing errors while retaining successful values.
import json
import subprocess

source = '[{"a":1}, 2, {"a":3}]'
result = subprocess.run(
    ["./jq", "-c", "[.[] | .a?]"],
    input=source + "\n",
    capture_output=True,
    text=True,
)
assert result.returncode == 0
actual = json.loads(result.stdout)
assert actual == [1, 3]
=== END AC conditionals-optional ===

## User Acceptance

- None.

## Guardrails

- Treat only `false` and `null` as false in conditional tests.
- Preserve generator ordering in `//` and conditional branches.
- Optional expressions must suppress only the enclosed runtime failure.

# FEATURE: Control Errors

| Field       | Value |
|-------------|-------|
| Version     | 20260816 V1 |
| Description | Implement jq runtime errors, exception recovery, halt behavior, and halt_error. |
| Depends On  | FEATURE-Control-Conditionals.md, FEATURE-CLI-Errors.md |
| Provides    | try/catch, error, halt, halt_error |
| Consumes    | evaluator, CLI exit mapping |

## Questions

- None.

## Intent

Runtime errors are structured jq values that may be caught by `try ... catch`. Uncaught runtime failures use exit status 5. `halt` stops successfully, while `halt_error` stops with its requested exit code. Values emitted before an error remain on stdout.

## Programmatic Acceptance

=== AC errors-try-catch ===
Intent: try/catch converts an error value into handler output.
import json
import subprocess

result = subprocess.run(
    ["./jq", "-c", 'try error("failure") catch .'],
    input="null\n",
    capture_output=True,
    text=True,
)
assert result.returncode == 0
actual = json.loads(result.stdout)
assert actual == "failure"
=== END AC errors-try-catch ===

=== AC errors-output-before-failure ===
Intent: Outputs produced before an uncaught runtime error remain available.
import json
import subprocess

result = subprocess.run(
    ["./jq", "-c", "1, error(2)"],
    input="null\n",
    capture_output=True,
    text=True,
)
assert result.returncode == 5
actual = [json.loads(line) for line in result.stdout.splitlines()]
assert actual == [1]
=== END AC errors-output-before-failure ===

=== AC errors-halt ===
Intent: halt stops evaluation successfully without emitting later values.
import subprocess

result = subprocess.run(
    ["./jq", "-c", '1, halt, 2'],
    input="null\n",
    capture_output=True,
    text=True,
)
assert result.returncode == 0
assert result.stdout.splitlines() == ["1"]
=== END AC errors-halt ===

=== AC errors-halt-error ===
Intent: halt_error terminates with its requested exit status.
import subprocess

exit_code = 7
result = subprocess.run(
    ["./jq", "-c", f'"failure" | halt_error({exit_code})'],
    input="null\n",
    capture_output=True,
    text=True,
)
assert result.returncode == exit_code
=== END AC errors-halt-error ===

## User Acceptance

- None.

## Guardrails

- Runtime failures must use exit status 5 unless halt_error explicitly supplies another status.
- Diagnostics belong on stderr.
- Preserve all values emitted before an uncaught runtime failure.
- Do not compare diagnostic wording as acceptance behavior.

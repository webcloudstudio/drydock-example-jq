<requirement name="implement-jq-interface" stories="cli-entrypoint,values-model">
The program is a filter: it is an executable file named `jq` at the application root, invoked as

```
./jq -c '<program>'
```

with JSON on **stdin**. It writes each value the program produces to **stdout** as one compact JSON value per line, and exits `0`.
</requirement>
<requirement name="implement-lexer" stories="frontend-lexer">
Lexer and parser. Follow `sources/lexer.l` and `sources/parser.y` directly. Produce an AST.
</requirement>
<requirement name="implement-parser" stories="frontend-parser">
Lexer and parser. Follow `sources/lexer.l` and `sources/parser.y` directly. Produce an AST. Precedence, `?` suffixes, string interpolation, and the `def` forms are all settled there.
</requirement>
<requirement name="reject-invalid-programs" stories="frontend-validation">
Reject invalid programs with exit `3`.
</requirement>
<requirement name="evaluate-generators" stories="eval-stream">
jq is a small language with a large semantic core. Almost every filter is a **generator**:
it takes one input and produces a stream of zero, one, or many outputs, and downstream
filters run once per upstream output.
</requirement>
<requirement name="implement-generator-core" stories="eval-core">
The generator core. Evaluate a filter as something that yields a stream of values:
`.`, literals, `|`, `,`, field access, iteration, arithmetic, comparison, and
`empty`.
</requirement>
<requirement name="evaluate-cartesian-products" stories="eval-cartesian">
Get `[.[] | f]`,
cartesian products over multi-output arguments, and short-circuiting right.
</requirement>
<requirement name="preserve-exit-codes" stories="cli-errors">
Exit codes follow jq's own, and the distinction is load-bearing because the harness grades

</requirement>
<requirement name="implement-control-flow" stories="control-conditionals,control-errors,control-reductions,control-recursion">
Control flow. `if`/`then`/`elif`/`else`/`end`, `try`/`catch` and `?`, `//`,
`reduce`, `foreach`, `label`/`break`, `limit`, `first`, `last`, `until`, `while`,
`recurse`.
</requirement>
<requirement name="implement-language-bindings" stories="language-functions,language-bindings,language-alternation">
Functions, variables, and destructuring. `def` with arity and closures, `as`
bindings, object and array patterns, and the `?//` alternative operator.
</requirement>
<requirement name="implement-path-operations" stories="paths-discovery,paths-helpers,paths-assignment">
Paths and assignment. `path(f)`, `getpath`, `setpath`, `delpaths`, `del`, and then
`=`, `|=`, `+=`, and friends.
</requirement>
<requirement name="implement-builtins" stories="builtins-collections,builtins-strings,builtins-regex,builtins-formats,builtins-utilities">
Builtins. Work outward from `sources/builtin.jq` and the manual: strings, arrays, objects,
`sort_by`/`group_by`/`unique_by`, `@base64`/`@uri`/`@csv`/`@tsv`/`@sh`
formats, the date functions, `tostream`, `input`/`inputs`, `$__loc__`, `debug`.
</requirement>
<requirement name="handle-numeric-edge-cases" stories="values-arithmetic,values-comparison">
Numbers and edge cases. `nan`, `infinite`, integer/float equality, large literals,
and the `have_decnum` builtin — return `false` from it and the corpus takes its
non-decNumber branch, which native floats satisfy.
</requirement>

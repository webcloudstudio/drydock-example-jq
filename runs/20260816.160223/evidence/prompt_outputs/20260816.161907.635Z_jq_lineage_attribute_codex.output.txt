<requirement name="stage-conformance-assets" stories="verify-assets">
This is the scoring instrument. It is supplied, not authored: it is staged verbatim into the build directory, hash-verified against the import, and restored before grading.
</requirement>
<requirement name="run-conformance-corpus" stories="verify-full">
Run the upstream jq conformance corpus against a candidate implementation.
</requirement>
<requirement name="execute-candidate-cases" stories="cli-entrypoint">
This runner re-implements the corpus protocol and drives the candidate as a subprocess, one process per case.
</requirement>
<requirement name="parse-corpus" stories="verify-full">
The format is documented in the corpus's own header: cases are groups of lines separated by blank lines; blank lines and lines starting with ``#`` are ignored.
</requirement>
<requirement name="honor-exclusions" stories="verify-full">
An exclusion that matches nothing is a hard error rather than a shrug.
</requirement>
<requirement name="compare-json-values" stories="values-model">
Structural, not textual: ``1`` and ``1.0`` are the same jq value and the corpus relies on that.
</requirement>
<requirement name="enforce-exit-contract" stories="frontend-validation,control-errors,cli-errors">
The corpus's %%FAIL cases are programs that must be rejected at compile time.
</requirement>
<requirement name="support-runner-interface" stories="cli-documentation">
JQ         command that runs the candidate. Required -- this harness is language-neutral
               and deliberately has no default implementation language.
</requirement>

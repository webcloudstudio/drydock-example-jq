<requirement name="jq-filter-language" stories="lexer,parser,compile-contract">
A jq program is a "filter": it takes an input, and produces an
output.
</requirement>
<requirement name="generator-streams" stories="generator-runtime">
Some jq operators and functions are actually generators in
that they can produce zero, one, or more values for each
input, just as one might expect in other programming
languages that have generators.
</requirement>
<requirement name="json-values-and-structure" stories="core-values">
jq supports the same set of datatypes as JSON - numbers,
strings, booleans, arrays, objects (which in JSON-speak are
hashes with only string keys), and "null".
</requirement>
<requirement name="operators-and-assignment" stories="operators">
Some jq operators (for instance, `+`) do different things
depending on the type of their arguments (arrays, numbers,
etc.). However, jq never does implicit type conversions.
</requirement>
<requirement name="errors-and-control-flow" stories="errors-control">
Errors can be caught by using `try EXP catch EXP`.
</requirement>
<requirement name="functions-variables-and-modules" stories="functions-bindings">
It is also possible to define functions in jq, although this
is is a feature whose biggest use is defining jq's standard
library (many jq functions such as `map` and `select` are in
fact written in jq).
</requirement>
<requirement name="reductions-and-recursion" stories="reductions">
The `reduce` syntax allows you to combine all of the results of
an expression by accumulating them into a single answer.
</requirement>
<requirement name="structural-builtins" stories="structural-builtins">
For any filter `f`, `map(f)` and `map_values(f)` apply `f`
to each of the values in the input array or object, that is,
to the values of `.[]`.
</requirement>
<requirement name="regular-expression-builtins" stories="regex-builtins">
jq uses the
[Oniguruma regular expression library](https://github.com/kkos/oniguruma/blob/master/doc/RE),
as do PHP, TextMate, Sublime Text, etc, so the description here will focus on jq specifics.
</requirement>
<requirement name="numeric-and-math-builtins" stories="numeric-builtins">
jq currently only has IEEE754 double-precision (64-bit) floating
point number support.
</requirement>
<requirement name="dates-json-encoding-and-environment" stories="date-json-encoding">
jq provides some basic date handling functionality, with some
high-level and low-level builtins. In all cases these
builtins deal exclusively with time in UTC.
</requirement>
<requirement name="format-and-escaping-filters" stories="formats">
The `@foo` syntax is used to format and escape strings,
which is useful for building URLs, documents in a language
like HTML or XML, and so forth.
</requirement>
<requirement name="io-and-streaming" stories="io-streaming,executable">
At this time jq has minimal support for I/O, mostly in the
form of control over when inputs are read.
</requirement>
<requirement name="sql-and-introspection-builtins" stories="sql-introspection">
jq provides a few SQL-style operators.
</requirement>

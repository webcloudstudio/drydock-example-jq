# ARCHITECTURE: jq Interpreter

| Field       | Value |
|-------------|-------|

| Depends On  | TECHNOLOGY_STACK.md, COMPASS.md |
| Provides    | interpreter module boundaries, executable contract |
| Consumes    | — |

## Questions

- None.

## Intent

The application is a standalone command-line jq-language interpreter. The root executable `jq` accepts `-c '<program>'`, reads JSON values from standard input, evaluates the program as an ordered stream of values, and writes compact JSON values to standard output.

## Boundaries

| Boundary | Responsibility |
|---|---|
| `jq` entry point | Argument validation, process startup, and exit-code mapping. |
| Lexer | jq tokens, literals, strings, comments, formats, and interpolation delimiters. |
| Parser/compiler | Grammar, precedence, AST construction, static validation, definitions, and module grammar. |
| Evaluator | Generator streams, lexical environments, functions, errors, control flow, and immutable values. |
| Builtin library | jq-defined functions and Python standard-library builtin implementations. |
| Input/output layer | JSON-lines input, compact serialization, diagnostics, environment, and auxiliary input streams. |
| Conformance assets | Read-only corpus, manual, grammar references, exclusions, and scoring harness. |

The evaluator must represent a filter as a stream-producing computation. It must preserve output order, multiplicity, cartesian products, backtracking, and short-circuit behavior. Values are immutable from the language's perspective; assignments produce replacement values.

## Technology Stack

- Python 3.11 or newer, standard library only, for the interpreter and tests.
- POSIX shell for the supplied conformance entry point.
- No third-party runtime dependency, jq binding, system jq invocation, network access, or installation step.

## Process Contract

The executable accepts only the exercised `-c` interface. Compile failures exit `3`; runtime failures exit `5`; successful completion exits `0`. Diagnostics go to stderr. Produced JSON values go to stdout, one compact value per line.

The implementation must never shell out to a system jq executable.

## Source Assets

The supplied files under `sources/` are immutable scoring and specification assets. The implementation may read them but must not modify `jq.test`, `exclusions.txt`, `run_conformance.py`, `full_test.sh`, `builtin.jq`, the manual, lexer, or parser references.

# FEATURE: Command-Line Entry

| Field       | Value |
|-------------|-------|
| Version     | 20260816 V1 |
| Description | Provides the executable jq entry point and its compact filter invocation contract. |
| Depends On  | ARCHITECTURE.md |
| Provides    | ./jq -c program execution |
| Consumes    | interpreter module boundaries |

## Questions

- None.

## Workflow

1. Start the executable at the application root.
2. Accept `-c` followed by one jq program.
3. Read JSON input from stdin.
4. Evaluate the program for each input value.
5. Emit every produced value as compact JSON on its own stdout line.
6. Return the interpreter's documented status.

The command must run directly from the application directory without installation or network access.

## Interface

```text
./jq -c '<program>'
stdin: JSON values
stdout: one compact JSON value per produced result, per line
```

Only `-c` is required by the supplied corpus. Unsupported options may be rejected.

## Programmatic Acceptance

=== AC entry-executable ===
Intent: The root jq executable accepts the documented compact-filter invocation.

import subprocess

payload = "null\n"
result = subprocess.run(
    ["./jq", "-c", "."],
    input=payload,
    capture_output=True,
    text=True,
)
print(result.stdout)
print(result.stderr)
assert result.returncode == 0

=== AC entry-stdin-output ===
Intent: The executable evaluates a filter supplied through -c and emits a JSON result.

import json
import subprocess

payload = '{"value": 7}\n'
program = ".value"
result = subprocess.run(
    ["./jq", "-c", program],
    input=payload,
    capture_output=True,
    text=True,
)
print(result.stdout)
print(result.stderr)
assert result.returncode == 0
values = [json.loads(line) for line in result.stdout.splitlines()]
assert values == [json.loads(payload)["value"]]

=== AC entry-multiple-results ===
Intent: The executable preserves multiple produced values as separate output lines.

import json
import subprocess

payload = "null\n"
program = "1,2"
result = subprocess.run(
    ["./jq", "-c", program],
    input=payload,
    capture_output=True,
    text=True,
)
print(result.stdout)
print(result.stderr)
assert result.returncode == 0
assert [json.loads(line) for line in result.stdout.splitlines()] == [1, 2]

## User Acceptance

- None.

## Guardrails

- The executable must be named `jq` and be executable at the application root.
- Do not require installation, network access, or configuration outside the supplied contract.
- Do not alter output order or collapse multiple generated values.

# FEATURE: Command-Line Errors

| Field       | Value |
|-------------|-------|
| Version     | 20260816 V1 |
| Description | Provides jq compile-failure, runtime-failure, and diagnostic routing behavior. |
| Depends On  | ARCHITECTURE.md, FEATURE-Command-Line-Entry.md |
| Provides    | compile exit 3, runtime exit 5, stderr diagnostics |
| Consumes    | ./jq -c program execution |

## Questions

- None.

## Error Contract

- Invalid jq syntax or static validation failure exits `3`.
- A program that compiles but raises during evaluation exits `5`.
- Successful execution exits `0`.
- Diagnostics are written to stderr and are not mixed into produced stdout values.
- Values produced before a runtime error remain valid output.

## Programmatic Acceptance

=== AC errors-compile-status ===
Intent: An invalid jq program is rejected with compile exit status 3.

import subprocess

result = subprocess.run(
    ["./jq", "-c", "{"],
    input="null\n",
    capture_output=True,
    text=True,
)
print(result.stdout)
print(result.stderr)
assert result.returncode == 3

=== AC errors-runtime-status ===
Intent: A compiling program that raises at runtime exits with status 5.

import subprocess

result = subprocess.run(
    ["./jq", "-c", "error"],
    input="null\n",
    capture_output=True,
    text=True,
)
print(result.stdout)
print(result.stderr)
assert result.returncode == 5

=== AC errors-diagnostic-routing ===
Intent: Runtime diagnostics are emitted on stderr while stdout remains a JSON-value channel.

import json
import subprocess

result = subprocess.run(
    ["./jq", "-c", "error"],
    input="null\n",
    capture_output=True,
    text=True,
)
print(result.stdout)
print(result.stderr)
assert result.returncode == 5
assert result.stdout == ""
assert result.stderr != ""
try:
    json.loads(result.stdout)
except json.JSONDecodeError:
    pass

=== AC errors-success-status ===
Intent: A valid non-raising program exits successfully.

import subprocess

result = subprocess.run(
    ["./jq", "-c", "."],
    input="null\n",
    capture_output=True,
    text=True,
)
print(result.stdout)
print(result.stderr)
assert result.returncode == 0

## User Acceptance

- None.

## Guardrails

- Exit codes must remain exactly 3 for compile failures and 5 for runtime failures.
- Diagnostics must never be emitted as produced JSON values.
- Do not compare or depend on exact diagnostic wording.

# FEATURE: Command-Line IO

| Field       | Value |
|-------------|-------|
| Version     | 20260816 V1 |
| Description | Provides JSON input parsing and compact ordered JSON-lines output. |
| Depends On  | ARCHITECTURE.md, FEATURE-Command-Line-Entry.md |
| Provides    | JSON stdin reader and JSON-lines stdout writer |
| Consumes    | ./jq -c program execution |

## Questions

- None.

## Input and Output Behavior

The process reads JSON values from standard input in the corpus format, including multiple values on separate lines. Each value becomes an input to the jq program. Every produced result is serialized as one compact JSON value followed by a newline.

Output number, order, and multiplicity are preserved. No pretty-printing, labels, or diagnostic text may be written to stdout.

The serializer must support the JSON values exercised by the corpus, including Unicode strings and jq special numeric behavior as required by the interpreter contract.

## Programmatic Acceptance

=== AC io-multiple-inputs ===
Intent: Multiple JSON input values are independently processed and emitted in input order.

import json
import subprocess

payload = "1\n2\n3\n"
program = ". + 1"
result = subprocess.run(
    ["./jq", "-c", program],
    input=payload,
    capture_output=True,
    text=True,
)
print(result.stdout)
print(result.stderr)
assert result.returncode == 0
inputs = [json.loads(line) for line in payload.splitlines()]
actual = [json.loads(line) for line in result.stdout.splitlines()]
assert actual == [value + 1 for value in inputs]

=== AC io-compact-lines ===
Intent: Each output value occupies one compact JSON line.

import subprocess

payload = '{"a": [1, 2]}\n'
result = subprocess.run(
    ["./jq", "-c", "."],
    input=payload,
    capture_output=True,
    text=True,
)
print(result.stdout)
print(result.stderr)
assert result.returncode == 0
assert result.stdout == '{"a":[1,2]}\n'

=== AC io-order-multiplicity ===
Intent: Generator output order and multiplicity are preserved by the output layer.

import json
import subprocess

payload = "null\n"
result = subprocess.run(
    ["./jq", "-c", '"first","second","first"'],
    input=payload,
    capture_output=True,
    text=True,
)
print(result.stdout)
print(result.stderr)
assert result.returncode == 0
expected = ["first", "second", "first"]
actual = [json.loads(line) for line in result.stdout.splitlines()]
assert actual == expected

=== AC io-unicode-json ===
Intent: Unicode JSON input and output round-trip through the compact serializer.

import json
import subprocess

value = "μ"
payload = json.dumps(value, ensure_ascii=False) + "\n"
result = subprocess.run(
    ["./jq", "-c", "."],
    input=payload,
    capture_output=True,
    text=True,
)
print(result.stdout)
print(result.stderr)
assert result.returncode == 0
assert json.loads(result.stdout) == value

## User Acceptance

- None.

## Guardrails

- Keep stdout exclusively for compact JSON result values.
- Preserve input and output ordering and generator multiplicity.
- Do not modify the supplied corpus or conformance runner.

## Questions

- None.

## Lexical Scope

The lexer recognizes:

- JSON-compatible literals, including integers, decimals, exponents, booleans, and null through parser-level identifiers.
- Identifiers, field names, variable bindings, and qualified names.
- Operators and delimiters, including arithmetic, comparison, assignment, pipe, comma, alternative, and control tokens.
- Array, object, and parenthesis delimiters with nesting validation.
- `#` comments, including escaped line continuation behavior.
- Quoted strings, JSON escapes, Unicode escapes, and interpolation delimiters `\(` and `)`.
- Format tokens such as `@json`, `@uri`, and `@base64`.

Invalid escapes and invalid characters must be reported as lexical compile failures. Tokenization must preserve source order and provide sufficient locations for diagnostics.

## Programmatic Acceptance

=== AC lexer-valid-source ===
Intent: The lexer accepts representative literals, identifiers, bindings, operators, comments, and formats.

import subprocess

    ["./jq", "-c", program],
    input="2\n",
    capture_output=True,
    text=True,
)
print(result.stdout)
print(result.stderr)
assert result.returncode == 0

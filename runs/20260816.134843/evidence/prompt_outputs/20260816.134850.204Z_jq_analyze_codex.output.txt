## Planning Instructions

### Delivery Shape

Deliver a standalone executable Python jq interpreter. It accepts jq source through `-c`, reads JSON from stdin, evaluates filters as ordered generators, and writes compact JSON outputs to stdout. The staged corpus and harness provide terminal verification.

### Story Realization Map

- `COMMAND-LINE-RUNTIME-*`: executable entry point and process contract; evidence `sources/INSTRUCTIONS.md`.
- `JQ-FRONT-END-*`: lexer/parser and syntax behavior; evidence `sources/lexer.l`, `sources/parser.y`, `sources/jq.test`.
- `GENERATOR-EVALUATION-*`: core stream semantics; evidence `sources/INSTRUCTIONS.md`, `sources/jq-manual.txt`, `sources/jq.test`.
- `VARIABLES-FUNCTIONS-*`: bindings, closures, definitions; evidence `sources/parser.y`, `sources/jq-manual.txt`, `sources/jq.test`.
- `DATA-TRANSFORMATION-*`: collections, paths, assignments, ordering; evidence `sources/builtin.jq`, `sources/jq-manual.txt`, `sources/jq.test`.
- `STRING-REGEX-*`: string, regex, and format behavior; evidence `sources/builtin.jq`, `sources/jq-manual.txt`, `sources/jq.test`.
- `CONTROL-MATH-*`: control flow, math, dates, I/O, streaming; evidence `sources/builtin.jq`, `sources/jq-manual.txt`, `sources/jq.test`.
- `MODULE-LIBRARY-*`: builtin library and module grammar; evidence `sources/builtin.jq`, `sources/parser.y`, `sources/jq.test`, `sources/exclusions.txt`.
- `CONFORMANCE-DELIVERY-*`: staged assets, terminal verification, and documentation; evidence `sources/full_test.sh`, `sources/run_conformance.py`, `sources/INSTRUCTIONS.md`.

The scopes require capabilities, with the conformance story requiring the test harness and acceptance contract.

### Test and Acceptance Strategy

Each implementation story uses focused tests or selected corpus cases owned by its feature. The complete corpus is reserved for `CONFORMANCE-DELIVERY-002`, whose acceptance assertion declares `Suite: full` and gates the project. All other corpus execution remains scoped.

### Sequencing and Dependencies

Stage source assets before verification. Implement the executable contract, lexer, parser, and generator core before dependent builtins. Implement paths before assignments; variables and functions before the jq-defined builtin library; all implementation features before the terminal full-suite story. No external service or persistence dependency exists.

### Source Conflicts and Gaps

No conflicting product definitions were found. The source does not specify a display name or short description; these are presented for Commander confirmation. Deployment is a local executable workflow defined by the supplied harness.

# COMPASS: jq

## Compass

Build a standalone jq-language interpreter for developers and automation that reads JSON from stdin, evaluates jq filters, and emits compact JSON values. The supplied jq 1.8.2 corpus and runner define correctness; the implementation must be usable through the fixed executable contract and complete the language semantics needed by the corpus.

## Constraints

- Implement in Python using only the standard library.
- Provide an executable named `jq` at the application root.
- Support the exercised `-c '<program>'` interface.
- Preserve the supplied source assets and run without installation or network access.
- Respect jq exit codes: 0 for success, 3 for compile failure, and 5 for runtime failure.
- Keep module-loader exclusions represented by the supplied exclusions file.

## Guardrails

- Never shell out to a system jq executable.
- Never use a third-party jq implementation or binding.
- Never modify the supplied corpus, harness, exclusions, or scoring script.
- Preserve generator ordering, multiplicity, and backtracking semantics.
- Write diagnostics to stderr and produced JSON values to stdout.

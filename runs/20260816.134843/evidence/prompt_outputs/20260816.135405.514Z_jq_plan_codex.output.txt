# FEATURE: Control and Recovery

| Field       | Value |
|-------------|-------|
| Version     | 20260816 V1 |
| Description | Provides jq conditionals, error recovery, halting, labels, and breaks. |
| Depends On  | ARCHITECTURE.md, FEATURE-Generator-Core.md, FEATURE-Operators-and-Comparisons.md |
| Provides    | if/then/else/elif/end, try, catch, ?, error, halt, halt_error, label, break |
| Consumes    | ordered filter streams, arithmetic and boolean operators |

## Questions

- None.

## Purpose

Implement jq control-flow and recovery semantics over ordered generator streams. Conditions treat only `false` and `null` as false. Errors propagate through generator evaluation unless handled by `try`, `catch`, or `?`.

## Behavior

- `if` evaluates each condition result and selects the corresponding branch.
- `try EXP catch HANDLER` evaluates the handler with the error value; `try EXP` suppresses errors.
- `error`, `halt`, and `halt_error` provide runtime termination with the documented status behavior.
- Labels and lexical breaks terminate the nearest visible labeled expression.
- Runtime diagnostics are emitted to stderr while values produced before an error remain observable.

## Programmatic Acceptance

=== AC control-recovery-conformance ===
Intent: The authoritative corpus cases for conditionals, recovery, errors, and labels pass.
Suite: scoped

import os
import subprocess
import sys

result = subprocess.run(
    [sys.executable, "sources/run_conformance.py", "--select",
     r"^(if |try |.*\?|.*error|.*halt|.*label|.*break)"],
    capture_output=True,
    text=True,
    env={**os.environ, "JQ": "./jq"},
)
print(result.stdout)
print(result.stderr, file=sys.stderr)
assert result.returncode == 0
=== END AC control-recovery-conformance ===

=== AC control-recovery-exit-contract ===
Intent: A runtime error uses the documented runtime failure exit status.
Suite: scoped

import os
import subprocess

program = "error(\"x\")"
result = subprocess.run(
    ["./jq", "-c", program],
    input="null\n",
    capture_output=True,
    text=True,
)
assert result.returncode == 5
=== END AC control-recovery-exit-contract ===

## User Acceptance

- None.

## Guardrails

- Do not convert runtime errors into compile failures.
- Preserve values emitted before a later generator failure.
- Do not write diagnostics to stdout.
- Do not shell out to a system jq executable.

# FEATURE: Variables and Destructuring Patterns

| Field       | Value |
|-------------|-------|
| Version     | 20260816 V1 |
| Description | Provides lexical bindings, destructuring patterns, and destructuring alternatives. |
| Depends On  | ARCHITECTURE.md, FEATURE-Generator-Core.md, FEATURE-Control-Recovery.md |
| Provides    | as bindings, lexical scope, array/object patterns, ?// alternatives |
| Consumes    | ordered filter streams, control and recovery semantics |

## Questions

- None.

## Purpose

Implement immutable lexical variable bindings and structural patterns used by jq's `as` operator and destructuring alternative operator.

## Behavior

- `EXP as $name | REST` evaluates `EXP` as a generator and runs `REST` with the original input and each bound value.
- Array and object patterns bind fields and positions, using `null` for missing array positions or unmatched named fields.
- Bindings are lexical and immutable; nested bindings shadow outer bindings only within their scope.
- `?//` tries alternatives when destructuring fails or the subsequent expression raises an error, exposing the variables declared by the successful alternative.

# FEATURE: User-Defined Functions

| Field       | Value |
|-------------|-------|
| Version     | 20260816 V1 |
| Description | Provides jq function definitions, filter and value arguments, recursion, closures, and redefinition. |
| Depends On  | ARCHITECTURE.md, FEATURE-Variables-and-Patterns.md |
| Provides    | jq function definitions, calls, arities, recursion, redefinition, closures |
| Consumes    | lexical bindings and destructuring patterns |

## Questions

- None.

## Purpose

Implement jq's lexical function system, including zero-argument filters, filter arguments, value arguments, overloads by arity, recursive definitions, closures, and later redefinitions.

## Behavior

- Definitions are visible only to expressions lexically to their right, except that a function may refer to itself.
- Filter parameters are invoked as filters against the current input; `$` parameters capture values.
- Calls evaluate generator arguments with jq's cartesian-product and backtracking semantics.
- Functions with the same name may coexist at different arities; redefining an arity replaces that definition for later references.
- Closures capture the lexical environment at definition time.

# FEATURE: Paths and Assignments

| Field       | Value |
|-------------|-------|
| Version     | 20260816 V1 |
| Description | Provides jq path discovery, lookup, deletion, and immutable assignment operators. |
| Depends On  | ARCHITECTURE.md, FEATURE-Indexing-and-Slicing.md, FEATURE-Control-Recovery.md, FEATURE-Variables-and-Patterns.md |
| Provides    | path, paths, getpath, setpath, delpaths, del, =, |=, +=, -=, *=, /=, %=, //= |
| Consumes    | ordered filter streams, indexing and slicing, lexical bindings |

## Questions

- None.

## Purpose

Implement jq's path model and immutable assignment semantics for objects, arrays, slices, iterators, and dynamically created intermediate structures.

## Behavior

- `path` emits path arrays for exact and matching path expressions; `paths` excludes the root path.
- `getpath`, `setpath`, and `delpaths` operate on path arrays with jq's null-filling and deletion rules.
- Plain assignment evaluates the right-hand side against the original input and uses every RHS output.
- Update assignment evaluates the RHS against each selected old value and uses only its first output; `empty` deletes the selected path.
- Assignment returns new immutable values and preserves unrelated fields and array elements.
- Invalid path operations raise runtime errors with exit status 5 when uncaught.

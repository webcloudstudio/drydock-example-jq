# Blueprint Analysis: jq

## Commander Expectations

- assert the jq interpreter passes every supplied jq 1.8.2 conformance case that is not declared excluded.
- assert the executable reads jq programs and JSON from stdin and emits compact JSON values with the documented exit codes.
- assert implementation uses only the Python standard library and does not rely on third-party jq implementations or a system jq binary.

## Planning Instructions

### Delivery Shape

Deliver a standalone Python executable implementing a jq-language interpreter. It accepts jq source through `-c`, reads JSON input streams, evaluates generator-based filters, and writes compact JSON output lines. The staged corpus and harness provide scoped development verification and one terminal full-suite proof.

### Test and Acceptance Strategy

Each implementation story uses focused unit and corpus slices during development. The complete corpus is never used as an intermediate story gate. `VERIFY-001` is the sole terminal story with `Suite: full` and runs the supplied full test script.

### Sequencing and Dependencies

Build the executable contract first, then lexer and parser, then the stream evaluator. Add paths and assignment before dependent builtins. Add functions and control flow before generator-heavy standard builtins. Stage all harness assets before verification. The final full-suite story depends on every implementation story.

### Source Conflicts and Gaps

No conflicting product definitions were found. The source is explicit that module-loader cases are excluded while module grammar cases remain scored. Identity confirmation remains an open Commander questionnaire.

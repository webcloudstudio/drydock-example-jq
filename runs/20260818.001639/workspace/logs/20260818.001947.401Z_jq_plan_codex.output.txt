## Questions

- None.

## Intent

The application is a standalone executable named `jq`. It accepts a jq program through `-c`, reads a sequence of JSON values from standard input, evaluates the program as an ordered generator, and writes each produced value as compact JSON on its own output line.

## Module Boundaries

| Module | Responsibility |
|---|---|
| `jq` | Executable process boundary, argument validation, input loop, output loop, and exit status mapping |
| `jq_lexer.py` | jq tokenization, comments, literals, escapes, interpolation, formats, and delimiters |
| `jq_parser.py` | Precedence-aware parsing and AST construction |
| `jq_runtime.py` | Generator evaluation, lexical environments, functions, errors, control flow, and path operations |
| `jq_builtins.py` | Standard jq filters and format, date, math, regex, streaming, and metadata functions |
| `jq_values.py` | JSON values, numeric handling, structural comparison, copying, and serialization |

The evaluator consumes AST nodes with an input value and lexical environment and produces an ordered Python generator. Collection constructs materialize generators only where jq requires an array or object result.

## Runtime Contract

- Compile failures write diagnostics to standard error and exit `3`.
- Runtime failures write diagnostics to standard error and exit `5`.
- Successful completion exits `0`.
- Values emitted before a runtime failure remain on standard output.
- The implementation uses only Python’s standard library and never invokes a system jq executable or third-party jq implementation.

## Source Assets

The supplied assets remain under `sources/` and are treated as read-only:

- `jq-manual.txt` and `jq.test` define language behavior and conformance.
- `lexer.l` and `parser.y` define front-end syntax.
- `builtin.jq` provides builtin reference definitions.
- `run_conformance.py`, `full_test.sh`, and `exclusions.txt` define verification.

## Technology Stack

- Python 3.11 or newer, standard library only, for the executable and interpreter.
- POSIX `sh` for the supplied scoring entry point.

=== AC architecture-runtime-statuses ===
Intent: The architecture exposes the three process statuses required by the jq contract.

import ast
from pathlib import Path

source = Path("sources/run_conformance.py").read_text(encoding="utf-8")
tree = ast.parse(source)
constants = {
    node.targets[0].id: node.value.value
    for node in tree.body
    if isinstance(node, ast.Assign)
    and len(node.targets) == 1
    and isinstance(node.targets[0], ast.Name)
    and isinstance(node.value, ast.Constant)
    and isinstance(node.value.value, int)
}
assert constants["EXIT_COMPILE_ERROR"] == 3
assert constants["EXIT_RUNTIME_ERROR"] == 5

import os
import subprocess
import sys
from pathlib import Path

root = Path.cwd()
result = subprocess.run(
    [sys.executable, "sources/run_conformance.py", "--list"],
    capture_output=True,
    text=True,
    env={**os.environ, "JQ": str(root / "jq")},
)
print(result.stdout)
print(result.stderr, file=sys.stderr)
assert result.returncode == 0

import runpy
runner = runpy.run_path("sources/run_conformance.py")
corpus = runner["parse_corpus"]((root / "sources/jq.test").read_text(encoding="utf-8"))
excluded = runner["apply_exclusions"](
    corpus,
    runner["parse_exclusions"](root / "sources/exclusions.txt"),

listed = [line for line in result.stdout.splitlines() if line.startswith(("run ", "skip "))]

assert sum(line.startswith("skip ") for line in listed) == len(excluded)

# jq

A standalone Python jq-language interpreter that reads JSON streams, evaluates jq filters, and emits compact JSON results.

## Intent

Run jq programs with:

```bash
./jq -c '<program>'
```

The program reads JSON values from standard input and writes each generated result as one compact JSON value per line.

Exit statuses are:

- `0` when compilation and evaluation complete successfully
- `3` when the jq program fails to compile
- `5` when evaluation raises a runtime error

The implementation uses only the Python standard library. Run the supplied conformance verification with:

```bash
sh sources/full_test.sh
```

## Scope

The lexer recognizes identifiers, fields, variable bindings, numeric and string literals, comments, operators, delimiters, formats, module keywords, string interpolation boundaries, and valid JSON escapes. It preserves source positions sufficiently for diagnostics.

## Programmatic Acceptance

    [sys.executable, "sources/run_conformance.py", "--select", selector],
    capture_output=True,
